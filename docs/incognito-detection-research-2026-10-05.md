# Исследование определения приватных окон браузеров

Дата: 2026-10-05.

Статус: исследование этапа 1.1 завершено, решение принято.

## Цель

Понять, может ли TimeTracker на Windows отличить обычное окно браузера от приватного без
чтения адреса страницы, внедрения в браузер и ложного обещания полной защиты.

Приватность нельзя строить на одном boolean, полученном из ненадёжной эвристики. Будущий
контракт детектора должен возвращать три состояния:

- `NORMAL` — окно уверенно распознано как обычное;
- `PRIVATE` — окно уверенно распознано как приватное;
- `UNKNOWN` — сигнал недоступен, противоречив или версия браузера не поддерживается.

При включённой защите от записи приватной активности `UNKNOWN` нельзя молча трактовать как
`NORMAL`.

- Windows x64, build 26200;
- язык интерфейса Windows и браузеров — русский;
- в каждом браузере одновременно открыты обычное и приватное окна;
- обычное окно содержит поисковый запрос «зоопарк»;
- приватное окно содержит поисковый запрос «шторм».

## Проверенные сигналы

Для каждого top-level окна были прочитаны без переключения фокуса и изменения браузера:

1. PID и путь executable;
2. Win32 window title;
3. класс, style/ex-style, owner и дочерние HWND;
4. командные строки browser/renderer-процессов;
5. Windows UI Automation tree: `Name`, `AutomationId`, `ClassName` и `ControlType`.

Поисковые запросы использовались только для ручного сопоставления окон. Они не являются
частью предлагаемого детектора.

Только по обычному Win32 title различимы три браузера: Яндекс, Edge и Firefox.

### Что означает «различим через UIA»

Windows UI Automation (UIA) — системный accessibility API, который используют экранные
дикторы и другие вспомогательные технологии. Через него браузер публикует элементы своего
интерфейса: кнопки, панели и их свойства `Name`, `ClassName` и `AutomationId`.

UIA не равен Win32 window title и не требует OCR, скриншота или доступа к DOM страницы.
Однако часть UIA-признаков тоже является локализованным текстом:

- Chrome: normal/private используют одинаковые `AvatarToolbarButton` и `view_1018`; режим
  различается по accessibility name кнопки;
- Edge: normal/private используют одинаковые `EdgeAvatarToolbarButton` и `view_1009`; режим
  различается по accessibility name;
- Яндекс и Firefox имеют явно приватные class names;
- Opera/Opera GX показали отдельные badge classes только в private, но эти имена не являются
  документированным внешним контрактом браузера;
- Brave показал `BraveAvatarToolbarButton` только в private/Tor в текущем профиле, но обычный
  профиль или будущая версия может добавить кнопку того же класса;
- Vivaldi не публикует пригодный признак.

Следовательно, можно не читать и не анализировать заголовок посещённой страницы, если искать
только ожидаемый toolbar-элемент UIA. Но полностью text-free детектор для всех семи браузеров
текущим тестом не подтверждён: Chrome и Edge требуют проверки небольшого accessibility label.

Отсутствие private-маркера само по себе нельзя считать доказательством `NORMAL`. Сначала
нужно подтвердить, что ожидаемая UIA-структура успешно прочитана. Неизвестная структура,
ошибка UIA или новая версия браузера должны давать `UNKNOWN`.

## Процесс не является границей приватности

Во всех восьми браузерах обычное и приватное top-level окна принадлежали одному browser PID.
У Chromium-браузеров дополнительные renderer/utility-процессы также не дают удобного
соответствия «этот HWND приватный». Командная строка общего browser-процесса не содержит
`--incognito`, когда приватное окно открыто из уже работающего браузера.

Следствия:

- нельзя исключать весь PID, не теряя обычные окна того же браузера;
- нельзя определять режим только по наличию `--incognito`;
- решение должно классифицировать конкретный foreground HWND.

### Brave Private Window with Tor

Дополнительный live-тест проведён с тремя одновременно открытыми окнами Brave:

- обычное окно с запросом «зоопарк»;
- обычное приватное окно с запросом «шторм»;
- приватное окно с Tor с запросом «ураган».

Все три окна принадлежали одному browser PID, имели класс `Chrome_WidgetWin_1`, а их Win32
titles не содержали признака режима. UI Automation показал:

- обычное окно — приватных маркеров нет;
- private — `BraveBrowserRootView` с `(Приватное)` и `BraveAvatarToolbarButton`
  «Это приватное окно»;
- private with Tor — `BraveBrowserRootView` с `(Приватное)` и тот же класс кнопки с именем
  `Tor`.

Для задачи TimeTracker оба последних режима достаточно классифицировать как `PRIVATE`.
Различие между private и private-with-Tor можно оставить диагностическим и не сохранять в
историю активности.

## Vivaldi

У обычного и приватного окон Vivaldi совпали:

- browser PID;
- класс `Chrome_WidgetWin_1`;
- window style и extended style;
- структура дочерних HWND;
- набор имён window properties;
- доступное UI Automation tree.

У Vivaldi есть отдельная настраиваемая тема приватных окон, поэтому анализ цвета или
скриншота не даёт устойчивой гарантии. Запуск отдельного экземпляра через `--incognito`
можно распознать только в ограниченном сценарии, но этот признак исчезает, когда обычное и
приватное окна находятся в одном уже запущенном процессе.

Предварительный вывод: без расширения или официального API Vivaldi нужно считать `UNKNOWN`.

## Вариант без расширения

Нативный детектор может работать только для foreground HWND:

1. определить браузер по нормализованному executable и metadata;
2. использовать быстрый проверенный title-маркер там, где он существует;
3. для Chrome, Opera, Opera GX и Brave читать ограниченную часть UI Automation tree;
4. возвращать `UNKNOWN`, если ожидаемая структура UIA отсутствует или изменилась;
5. перепроверять HWND и foreground до и после потенциально медленного UIA-запроса, как уже
   делает текущий foreground resolver.

Плюсы:

- не требует установки компонентов в браузер;
- первый live-тест покрывает семь браузеров;
- не требует доступа к URL и содержимому страницы.

Ограничения:

- accessibility labels локализованы и меняются между версиями;
- запрос UIA может быть медленным или временно недоступным;
- UIA способен активировать расширенный accessibility mode браузера, поэтому требуется
  отдельный CPU/latency benchmark;
- Vivaldi не поддержан;
- результат нельзя рекламировать как универсальную гарантию приватности.

WinEvent callback, перепроверять foreground HWND после ответа и отдельно сравнить CPU
браузеров до и после первого обращения к UIA.

## Вариант с companion extension

WebExtensions предоставляют признак incognito/private для окон и вкладок. Chromium и
Firefox оставляют доступ расширения к приватным окнам под контролем пользователя: после
установки расширению нужно отдельно разрешить работу в приватном режиме.

Расширение может передавать локальному TimeTracker только минимальное состояние через
Native Messaging, не передавая URL, title или содержимое страницы.

Плюсы:

- браузер сообщает режим явно;
- потенциально закрывает Vivaldi и снижает зависимость от локализованных подписей UIA;
- один WebExtensions-код можно адаптировать для Chromium-семейства и Firefox.

Ограничения:

- пользователь должен установить расширение в каждый браузер и разрешить private access;
- выключенное или сломанное расширение снова создаёт `UNKNOWN`;
- нужны регистрация Native Messaging host, распространение расширения и проверка доставки
  событий при быстрых переключениях окон;
- ещё требуется прототип сопоставления browser window с foreground HWND без передачи
  истории просмотра.

Официальные справочные материалы:

- [Chrome: incognito manifest mode](https://developer.chrome.com/docs/extensions/reference/manifest/incognito);
- [Chrome: Native Messaging](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging);
- [MDN: WebExtensions incognito](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/manifest.json/incognito);
- [Vivaldi: поддержка расширений Chrome Web Store](https://help.vivaldi.com/desktop/appearance-customization/extensions/).

## Принятое решение

### Детектор

Первая реализация использует нативный tri-state детектор foreground HWND:

- `NORMAL` — ожидаемая структура браузера успешно прочитана и приватный режим исключён;
- `PRIVATE` — найден подтверждённый private/incognito-маркер;
- `UNKNOWN` — UIA недоступен, структура изменилась, браузер не поддержан или результат
  противоречив.

Поддерживаемый набор первой версии: Chrome, Яндекс Браузер, Opera, Edge, Firefox, Brave и
Opera GX. Сопоставление выполняется по нормализованному пути executable и metadata, а режим
определяется для конкретного foreground HWND.

Расширение браузера не входит в первую реализацию. К нему можно вернуться, если нативная
диагностика окажется недостаточно устойчивой.

### Поведение записи

Настройка «Не отслеживать приватные окна браузеров» включает fail-closed поведение:

| Результат | Действие TimeTracker |
|---|---|
| `NORMAL` | обычная запись продолжается |
| `PRIVATE` | включается автоматическая пауза |
| `UNKNOWN` | включается автоматическая пауза с объяснением причины |

Автоматическая пауза имеет ту же границу данных, что ручная:

- текущие интервалы закрываются в момент подтверждённого переключения;
- пока защищаемое окно находится на foreground, новые process/running/foreground/system
  интервалы не записываются;
- при возврате к `NORMAL` или другому приложению выполняется свежий snapshot;
- приватный промежуток не восстанавливается задним числом;
- наличие приватного окна в фоне само по себе не останавливает запись.

Детектор не сохраняет и не логирует URL, title страницы или accessibility name. Для
диагностики допустимы только браузер, версия, тип использованного сигнала, итоговое состояние
и техническая причина `UNKNOWN`.

### Vivaldi

Для Vivaldi выбран безопасный первый вариант: при включённой защите любое foreground-окно
Vivaldi даёт `UNKNOWN` и включает автоматическую паузу. Пользователь должен видеть, что
TimeTracker не умеет отличить обычное окно Vivaldi от приватного, поэтому временно не
записывает браузер целиком.

### Обновления браузеров

Версия браузера сохраняется только в диагностике. Обновление само по себе не блокирует
браузер, если ожидаемая UIA-структура и маркер по-прежнему распознаются. Изменившаяся или
неполная структура должна давать `UNKNOWN`, а не предположение `NORMAL`.

## Приёмочные проверки реализации

Эти проверки относятся к будущему прототипу и этапу реализации, а не блокируют завершение
исследования:

- [x] Brave Private Window with Tor распознаётся как `PRIVATE`.
- [ ] Firefox в режиме «Всегда использовать приватный просмотр».
- [ ] Запуск каждого браузера сразу приватным, без предварительного обычного окна.
- [ ] Несколько обычных и приватных окон, быстрое переключение и закрытие активного окна.
- [ ] Русская и английская локали браузеров.
- [ ] Изменённая/неизвестная UIA-структура даёт `UNKNOWN`, а не `NORMAL`.
- [ ] Ошибка или timeout UIA даёт `UNKNOWN` и не блокирует worker.
- [ ] A/B-проверка CPU браузеров до и после первого обращения к UIA.
- [ ] В историю и обычный журнал не попадают URL, page title и accessibility name.
- [ ] Vivaldi всегда включает автопаузу при включённой защите.
- [ ] Возобновление создаёт свежий snapshot и не заполняет приватный промежуток.
