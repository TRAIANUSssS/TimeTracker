# Dashboard, автозапуск и Windows-сборка

Этап 5 реализует основную вкладку по референсу и UI-спеке. Светлый фон с розовыми
пятнами, Manrope, стеклянная таблица, десять строк с раскрытием, анимации прогресса
и перестановки, отдельные loading/error/empty состояния. `/advanced` и `/settings`
остаются предусмотренными заглушками. Настройки отдельных приложений доступны
через существующий API, без добавления незапрошенной settings UI.

## Фильтры и запросы

Первое открытие выбирает сегодня, 00:00–24:00 и только активные приложения.
Календарь принимает диапазон после второго клика; слайдер меняет выбор шагом
15 минут и отправляет запрос после отпускания. Ручной ввод сохраняет точные
минуты и подтверждается Enter/потерей фокуса. Escape отменяет правку.
Равные границы и неверные времена показывают ошибку без запроса. Ночное окно
помечается «До следующего дня». Timezone берётся из браузера.

Apps/system/activity имеют независимые generation IDs. AbortController дополняет
проверку поколения, а не заменяет её. Active-only запрашивает только apps;
date/time и refresh обновляют все три секции. Expand/collapse не делает запросов.
Refresh сохраняет фильтры и раскрытие. Автоматического периодического refresh нет.
При старых данных сохраняется их собственный способ нормализации progress bars
до получения нового ответа. При смене режима старая timeline не показывается как heatmap.

## Визуализации

Timeline размещает сегменты по абсолютным timestamps, оставляет no_data, unknown,
сон и будущее различимыми. Для шкалы без истории API передаёт полные выбранные
UTC-интервалы в `X-TimeTracker-Windows`; JSON по-прежнему является массивом.
Границы DST берутся с backend. Невыбранные промежутки между повторениями частичного
часа обозначаются штриховкой. Полночь — серая линия с датой, без дополнительной
длительности; tooltips включают даты и UTC offsets.

Heatmap переключается между датами и средними по ISO weekday на границе 14/15 дней.
Цвет использует intensity из API. Tooltips показывают фактическую дату/час,
активность и неполное покрытие. Missing hour, no_data и future имеют отдельные
стили; повторяющийся час учитывается в одной ячейке, ночные часы имеют `+1`.

Шрифт Manrope, SVG favicon, JS и CSS включены в локальные ресурсы; dashboard
не требует сети. API и frontend используют один origin. В Vite dev-mode только
локальный прокси направляет запросы на `127.0.0.1:8765`.

## Трей и автозапуск

Левый щелчок по розовым часам открывает dashboard в браузере, правый — меню:
«Открыть dashboard», пока недоступная пауза, «Запускать вместе с Windows», «Выход».
Открытие браузера использует фактический порт API, в том числе `--api-port`.

Автозапуск выключен по умолчанию и включается пользователем через меню.
Запись `TimeTracker` в `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`
содержит абсолютный путь, выбранную БД и порт. Запуск из исходников использует
pythonw, сборка — TimeTracker.exe. Аргументы экранируются Windows quoting;
права администратора не требуются. Команды длиннее лимита Run 260 символов
отклоняются, ошибка записывается в журнал. При перемещении приложения повторное
включение обновляет путь. Отключение удаляет только значение TimeTracker.

Браузер не открывается автоматически при входе в Windows: трекер начинает
запись в трее. Страница настроек остаётся заглушкой по UI-спеке.

## Сборка и распространение

Нужны Windows x64, Python 3.12+ и Node.js 22.12+ только на машине сборки:

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[dev,build]"
.\.venv\Scripts\python.exe packaging/build.py
```

`build.py` выполняет npm ci/build, рисует ICO из того же мотива часов, запускает
PyInstaller onedir/windowed и создаёт `dist/TimeTracker-windows-x64.zip`.
Включены frontend, шрифты, tzdata, нативные зависимости и лицензии библиотек.
Результат — переносимая папка `dist/TimeTracker`, без необходимости ставить
Python/Node или скачивать ресурсы на целевом компьютере. Это сборка без цифровой
подписи; установщик и автоматическое обновление не входят в этот этап.

Приложение хранит данные в `%LOCALAPPDATA%\TimeTracker`, вне своей папки.
Перед заменой файлов нужно завершить его через трей. Для переноса ZIP требуется
вся папка вместе с `_internal`, а не один exe. Сборка из исходников не изменяет
пользовательскую БД и не включает автозапуск на машине разработчика.

## Проверка полного приложения

Обычный Python-набор и браузерные проверки используют временные/искусственные данные.
Автозапуск проверяется настоящим реестром в отдельном временном ключе, не в Run.
Эта проверка подтверждает корректность команды и её удаления; фактический вход
в Windows после перезагрузки не имитируется.

Полная opt-in проверка собранного exe:

```powershell
$env:TIME_TRACKER_PACKAGED_SMOKE = '1'
.\.venv\Scripts\python.exe -m pytest tests/test_packaged_live.py -q
Remove-Item Env:TIME_TRACKER_PACKAGED_SMOKE
```

Она запускает exe в отдельной временной БД и на свободном порту, проверяет настоящий
сбор Windows, heartbeat, PATCH, tzdata/DST, dashboard и локальные assets, затем
браузером переключает фильтры и страницы с реальным API. Все внешние запросы
заблокированы проверкой. В конце отправляется штатное WM_CLOSE: ожидаются normal,
закрытые сессии, свободный порт и целая SQLite. Компьютер не блокируется и не
переводится в сон. Скриншот: `frontend/test-results/packaged-dashboard.png`.

Сборка и проверки выполнены на текущем Windows 11 x64. Тесты сна из этапов 3–4
сохраняют силу; этот этап не меняет источники питания или расчёт длительностей.

[Playwright](https://playwright.dev/docs/intro).
