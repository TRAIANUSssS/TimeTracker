# Пользовательское включение ETW

2026-09-13. Реализовано после часовой приёмки транспорта; этапы 6–8 сюда не входят.
Само приложение, интерфейс и SQLite работают с обычными правами. Фоновый компонент
собирает только события процессов и передаёт их через локальный pipe.

## Использование

1. Распаковать весь ZIP и запустить `TimeTracker.exe`.
2. Открыть «Настройки сбора» через трей или значок настроек в dashboard.
3. Нажать «Установить и выбрать экономичный режим». Установщик запрашивает UAC;
   у обычной учётной записи Windows можно ввести данные администратора. Компонент
   всё равно настраивается для исходного пользователя, чей SID передаёт приложение.
4. Дождаться завершения установки, выйти через трей и снова запустить приложение.
   В настройках должно появиться «экономичный режим работает».
5. Автозапуск включается прежним пунктом меню трея. При входе в Windows приложение
   читает сохранённый режим и запускает компонент без нового запроса UAC.

Обычный режим не требует установки. Выбор сохраняется в `collection-settings.json`
рядом с БД атомарной заменой файла; текущая сессия продолжает прежний режим до выхода.
Повреждённые настройки вызывают polling и сообщение об ошибке. Отмена UAC не меняет
режим. Не закрывать приложение до завершения установки: при закрытии оно может
не успеть сохранить новый режим, хотя Windows уже установит компонент. Тогда после
запуска достаточно выбрать ETW в настройках.

Отключение: выбрать обычный режим, перезапустить. Удаление: после этого нажать
«Удалить компонент» и подтвердить Windows. БД и история не удаляются. Для обновления
компонента также сначала перейти на polling и перезапустить, затем использовать
«Обновить / восстановить компонент» из нового полного пакета.

При недоступности сборщика текущая запись продолжается с polling 5 s. Интерфейс
показывает фактический режим отдельно от сохранённого выбора. Reader повторяет
попытку запуска/подключения через 5 s; сломанный компонент можно восстановить.
Fallback не восстанавливает пропущенные короткие процессы.

## Устройство

- Пакет содержит `collector/TimeTrackerETW/TimeTrackerETW.exe` и его `_internal`.
  Компонент собирается отдельным onedir-пакетом, не требует установленного Python.
- Установщик копирует его в защищённый `%ProgramFiles%/TimeTracker-ETW-<SID>`:
  `version-<SHA256 содержимого пакета>/TimeTrackerETW.exe` и зависимости.
  Пользователь может читать файлы, но не изменять их. Владелец — Administrators,
  запись разрешена Administrators и SYSTEM. Ссылки/junction отклоняются.
- Задача `TimeTracker-ETW-<SID>` работает под SYSTEM без сохранения пароля.
  Её единственное действие — установленный helper с фиксированными `--serve`
  и `--owner-sid`. Обычному пользователю разрешены чтение и запуск задачи,
  изменение команды/прав требует администратора.
- Триггер входа в Windows не нужен: задача запускается по запросу приложения,
  включая его прежний HKCU-автозапуск. В polling-режиме задача не запускается.
  Нет ограничения в 24/72 часа, запрета на батарее или пробуждения ПК по задаче.
- Сборщик ждёт reader до 60 s, затем завершается при его отсутствии. После
  подключения работает до finish или разрыва, освобождает ETW-сессию и выходит.
  При следующем запуске приложения или восстановлении reader запускает задачу снова.
- Pipe `managed` изолирован по SID, ACL разрешает только SYSTEM и этого пользователя.
  Повышенный процесс не читает настройки приложения, не открывает БД/HTTP и не
  исполняет команды, пути или скрипты из pipe. Поддерживается только finish.
- Один экономичный экземпляр на пользователя; изолированные benchmark-запуски
  по-прежнему могут использовать свои ручные каналы через `--process-events`.
- Запросы изменения настроек имеют строгую схему, проверку origin и токен текущего
  процесса. Настройка UAC выполняется отдельно от оконного потока/worker/SQLite;
  повторное действие блокируется до завершения текущего.

Журнал приложения: `logs/tracker.log` рядом с БД. Журнал компонента:
`%ProgramFiles%/TimeTracker-ETW-<SID>/collector.log`, ограничен по размеру с двумя копиями.
Обновление регистрирует новую задачу после проверки копии пакета. Запущенный компонент
обновлять/удалять нельзя. Старые версии удаляются после успешной регистрации новой.

Перед приёмкой пользовательского режима на готовой сборке проверить:

1. Отказ от UAC оставляет polling; повторное подтверждение устанавливает компонент.
2. После перезапуска ETW подключается без консоли/повторного UAC; короткие процессы,
   lock/unlock и sleep/wake продолжают сохраняться.
3. Выход подтверждает finish, следующий запуск снова подключает ETW.
4. Автозапуск после выхода/входа в Windows работает без UAC.
5. После перехода на polling и перезапуска обновление/удаление компонента проходят,
   история остаётся доступна; повторная установка работает.

Отмена UAC и обновление/удаление остаются отдельными ручными
проверками. Первичная установка пользователем и запуск установленной задачи
подтверждены ниже. Суточный тест запланирован после остальных этапов.

### Исправление локализованного имени SYSTEM, 2026-09-13

Пользователь установил компонент, но настройки показывали «Не удалось проверить
фоновый компонент Windows». Задача была создана корректно; Windows возвращала
`Principal.UserId` как локализованное имя «СИСТЕМА», хотя при регистрации передавался
SID `S-1-5-18`. Проверка сравнивала строки и ошибочно отклоняла задачу.

Теперь SID разрешается через Windows и сравнивается с `S-1-5-18`; текстовое имя
не определяет доверие. Добавлены тесты SID, английского, русского и французского
имени и отклонения другого SID. Причина отказа проверки записывается в журнал
один раз на одинаковую ошибку, без повторения каждые 3 s. Профильные тесты: 30 passed.

Существующая установленная задача успешно проверена и запущена обычным процессом
без повышения прав. Live-тест ETW → pipe → worker → отдельная БД:
`build/etw-integration/20260913T102815Z-51fa95d5/report.json`, passed=true,
shutdown_complete=true, finish_requested=true, source_incomplete=false,
worker_error=null. Оба контрольных процесса сохранены корректно, БД цела.
Для этого исправления достаточно обновить приложение; переустановка сборщика не нужна.
Исправленный ZIP пересобран; packaged smoke со страницей настроек и реальной
установленной задачей прошёл: 1 passed. Сборщик после live-теста завершился с кодом 0.

Основание механизма прав: [Microsoft Task Scheduler security contexts](https://learn.microsoft.com/en-us/windows/win32/taskschd/security-contexts-for-running-tasks).
